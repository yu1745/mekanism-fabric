# Packaged Fabric server smoke test

Run the final, remapped JAR in a clean dedicated server rather than Loom's development classpath:

```bash
scripts/fabric-packaged-smoke.sh
```

The script reads the pinned Minecraft, Loader, Fabric API, and Fabric Installer versions from `fabric/gradle.properties`, builds `remapJar`, downloads reusable dependencies into `${XDG_CACHE_HOME:-~/.cache}/mekanism-fabric-smoke`, and creates an EULA-accepted server only under a temporary directory. The audited slices contain API **42** / common **37** / platform **10** unique sources. The script rejects a mod JAR containing `net/neoforged/` or integration-fixture classes; verifies exact common/client entrypoint metadata and the single intended remapped access-widener entry plus packaged networking, energy-container, basic and variable heat-capacitor, relative-side, holder, and unchanged `WildcardMatcher` classes. It also requires exactly one entry each for `EmitUtils`, `SplitInfo`, `IntegerSplitInfo`, `LongSplitInfo`, `Target`, and `Target$HandlerType`, exactly one `mekanism/common/util/ChunkUtils.class`, and exactly one entry for the `LambdaMetaFactoryUtil` outer class, `CallSiteInfo`, and all five private primitive setter interfaces. It additionally requires exactly the six expected `mekanism/common/lib/collection/*.class` entries (`BiLongMultimap`, `FilterTransformIterator`, `IndexedCuboidMap`, its two anonymous iterators, and `CenteredBoundingBox`) while rejecting every other class in that package, and exactly one `RegistryUtils.class` and rejects every other `RegistryUtils*.class`, requires exactly one entry each for `mekanism/api/container/InContainerGetterLong.class`, `mekanism/api/container/LongToLongContainerInteraction.class`, and `mekanism/api/math/LongTransferUtils.class` while rejecting every other `LongTransferUtils*.class`, and requires the three strict energy-handler interfaces and the existing `IEnergyContainer` exactly once while rejecting every other energy API class outside the current closure. Every unexpected distribution, `ChunkUtils*`, `LambdaMetaFactoryUtil*`, or `LongTransferUtils*` class is likewise rejected so official/local test and helper classes cannot leak into the release JAR. It passes only after the server log lists mod id `mekanism`, records the clean `values=12` startup-config proof, records configuration-network registration for exact protocol `10.7.19`, parses `config/Mekanism/startup.toml` and compares all paths/defaults exactly, records the `entries=4` canonical proof for all official Mekanism GameEvents, invokes the access-widened position-adjusted biome-temperature path and records its finite-result heat proof, and reports `Done (`. The server process and temporary directory are removed on every exit.

Diagnostic logs are retained under `build/fabric-packaged-smoke/<UTC timestamp>-<pid>/`. Set `FABRIC_SMOKE_KEEP_SERVER=1` to retain the disposable server directory as well. Other useful overrides are `FABRIC_SMOKE_TIMEOUT`, `FABRIC_SMOKE_CACHE_DIR`, `FABRIC_SMOKE_LOG_DIR`, and `FABRIC_INSTALLER_VERSION`.

The networking marker proves codec/server-receiver registration and dedicated-server class-loading safety. Because this disposable server has no connecting client, it does **not** prove an actual configuration payload round trip. Matching round-trip across two sequential fresh client JVMs is covered separately by `scripts/fabric-paired-network-smoke.sh`; incompatible-version, same-version explicit client rejection, and missing-protocol rejection are covered by `scripts/fabric-configuration-rejection-smoke.sh`. Remaining network boundaries are listed in `FABRIC_NETWORK.md`.

The byte-identical codec closure has no startup marker. Packaging requires exactly `mekanism/api/codec/DependentMapCodec.class` and the three expected common entries (`DroppingUnboundedMapCodec`, `SequencedCollectionCodec`, and its `DecoderState`) once each, rejecting every other class in either package. Its five Java 21 tests provide the semantic proof; `ModuleContainer`, `AttachedSideConfig`, recipes, data components, config/network owners, all callers, and persistence/registry/packet/lifecycle/serialized-compatibility claims remain outside this gate.

The byte-identical collection closure, distribution, `ChunkUtils`, `RegistryUtils`, `LambdaMetaFactoryUtil`, the long-transfer utility closure, and the strict energy-handler closure deliberately have **no startup marker**: packaging proves only exact class presence and test/helper isolation. The three unchanged long-transfer production classes (`LongTransferUtils`, `InContainerGetterLong`, `LongToLongContainerInteraction`) are proved by Fabric-local Java 21 tests that observe call order, forwarded side/`Action`/`AutomationType`, shrinkable remainder/request values, and `SIMULATE` versus `EXECUTE` mutation (including true-`long` amounts above `Integer.MAX_VALUE`) rather than by constructing state during production bootstrap. The strict handler suites separately prove indexed non-empty-first/source-order aggregation, every unsided bridge's exact configured side, explicit nullable-side propagation, invalid-index/no-op defaults, negative-set clamping, null/internal versus non-null/external automation, and one side-specific list lookup per container-backed aggregate. `IStrictEnergyHandler` and `ISidedStrictEnergyHandler` differ from baseline only in fluid imports/Javadoc prose; `IMekanismStrictEnergyHandler` is byte-identical. This remains internal API proof, not external Energy API, conversion, lookup/transaction, configurable-holder, concrete `EnergyHandler`, owner/machine/network, or caller proof. `RegistryUtils` behavior is proved by Fabric-local tests covering canonical built-in holders/keys, all requested NBT ID outcomes, block paths, reference/direct and key-only/value-only unbound holder naming, registered/unknown objects, and the direct-holder short circuit. Its normal-vanilla-unreachable `getBEHolder` null fallback is not forced by mutating a registry, and this slice makes no caller, lifecycle, mutation, or custom-registry claim. Exact int/long split, rebalancing, remainder/fallback order, handler-contract behavior, `rangeClosed` traversal order, negative floor-section results, and the sequential non-empty-first insertion/source-order extraction semantics (including the supplier-extract zero-versus-negative short-circuit) belong to `fabric test`, which compiles the unchanged 18-file official root-test oracle (including two collection tests) through an explicit path allowlist and adds Fabric-local boundary suites. Java 21 tests separately prove that empty names use caller-accessible direct instance fields while non-empty names invoke exact named virtual methods (which may transform values), including all primitive boxing/unboxing branches, object/null behavior, per-instance reuse, and unnormalized lookup/access/invocation failures. Direct-field accessibility/module openness, exact `objType`/method signatures, instance fields, compatible boxed values, and non-null primitive setter values remain caller preconditions; static/final fields are outside this bounded contract. Collection boundary tests additionally prove duplicate/mutation results, sorted extreme keys and reverse consistency, null filtering/order/exhaustion, negative chunk and inclusive box edges, exact-box replacement, and mixed index cleanup. Miner/QIO/spatial callers, world/chunk lifecycle/loading, persistence, concurrency, and multi-thread mutation remain deferred and unclaimed. This utility prerequisite does not include `SyncMapper`, synchronization annotations, tracked data, containers, networking, reflection scanning, or any caller.

This gate performs no Docker, deployment queue, or production-server operations.
