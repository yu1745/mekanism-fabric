# Packaged Fabric server smoke test

Run the final, remapped JAR in a clean dedicated server rather than Loom's development classpath:

```bash
scripts/fabric-packaged-smoke.sh
```

The script reads the pinned Minecraft, Loader, Fabric API, and Fabric Installer versions from `fabric/gradle.properties`, builds `remapJar`, downloads reusable dependencies into `${XDG_CACHE_HOME:-~/.cache}/mekanism-fabric-smoke`, and creates an EULA-accepted server only under a temporary directory. The audited slices contain API **35** / common **32** / platform **10** sources. The script rejects a mod JAR containing `net/neoforged/` or integration-fixture classes; verifies exact common/client entrypoint metadata and the single intended remapped access-widener entry plus packaged networking, energy-container, basic and variable heat-capacitor, relative-side, holder, and unchanged `WildcardMatcher` classes. It also requires exactly one entry each for `EmitUtils`, `SplitInfo`, `IntegerSplitInfo`, `LongSplitInfo`, `Target`, and `Target$HandlerType`, exactly one `mekanism/common/util/ChunkUtils.class`, and exactly one entry for the `LambdaMetaFactoryUtil` outer class, `CallSiteInfo`, and all five private primitive setter interfaces. It additionally requires exactly one `RegistryUtils.class` and rejects every other `RegistryUtils*.class`. Every unexpected distribution, `ChunkUtils*`, or `LambdaMetaFactoryUtil*` class is likewise rejected so official/local test and helper classes cannot leak into the release JAR. It passes only after the server log lists mod id `mekanism`, records the clean `values=12` startup-config proof, records configuration-network registration for exact protocol `10.7.19`, parses `config/Mekanism/startup.toml` and compares all paths/defaults exactly, records the `entries=4` canonical proof for all official Mekanism GameEvents, invokes the access-widened position-adjusted biome-temperature path and records its finite-result heat proof, and reports `Done (`. The server process and temporary directory are removed on every exit.

Diagnostic logs are retained under `build/fabric-packaged-smoke/<UTC timestamp>-<pid>/`. Set `FABRIC_SMOKE_KEEP_SERVER=1` to retain the disposable server directory as well. Other useful overrides are `FABRIC_SMOKE_TIMEOUT`, `FABRIC_SMOKE_CACHE_DIR`, `FABRIC_SMOKE_LOG_DIR`, and `FABRIC_INSTALLER_VERSION`.

The networking marker proves codec/server-receiver registration and dedicated-server class-loading safety. Because this disposable server has no connecting client, it does **not** prove an actual configuration payload round trip. Matching round-trip across two sequential fresh client JVMs is covered separately by `scripts/fabric-paired-network-smoke.sh`; incompatible-version, same-version explicit client rejection, and missing-protocol rejection are covered by `scripts/fabric-configuration-rejection-smoke.sh`. Remaining network boundaries are listed in `FABRIC_NETWORK.md`.

Distribution, `ChunkUtils`, `RegistryUtils`, and `LambdaMetaFactoryUtil` deliberately have **no startup marker**: packaging proves only exact class presence and test/helper isolation. `RegistryUtils` behavior is proved by Fabric-local tests covering canonical built-in holders/keys, all requested NBT ID outcomes, block paths, reference/direct holder naming, registered/unknown objects, and the direct-holder short circuit. Its normal-vanilla-unreachable `getBEHolder` null fallback is not forced by mutating a registry, and this slice makes no caller, lifecycle, mutation, or custom-registry claim. Exact int/long split, rebalancing, remainder/fallback order, handler-contract behavior, `rangeClosed` traversal order, and negative floor-section results belong to `fabric test`, which compiles the unchanged 16-file official root-test oracle through an explicit path allowlist and adds Fabric-local boundary suites. Java 21 tests separately prove that empty names use caller-accessible direct instance fields while non-empty names invoke exact named virtual methods (which may transform values), including all primitive boxing/unboxing branches, object/null behavior, per-instance reuse, and unnormalized lookup/access/invocation failures. Direct-field accessibility/module openness, exact `objType`/method signatures, instance fields, compatible boxed values, and non-null primitive setter values remain caller preconditions; static/final fields are outside this bounded contract. This utility prerequisite does not include `SyncMapper`, synchronization annotations, tracked data, containers, networking, reflection scanning, or any caller.

This gate performs no Docker, deployment queue, or production-server operations.
