## Smoke probe facts (not recorded elsewhere)

Written via `data merge block` in `scripts/fabric-machine-smoke.sh` and any new probes:

- Inventory slots: `items:[{slot:0b,item:{id:"minecraft:iron_ore",count:2}}]`
- Energy containers: `energy_containers:[{container:0b,stored:20000L}]`
- Fluid tanks: `fluid_tanks:[{tank:0b,stored:{id:"minecraft:water",amount:8000}}]`
- Chemical tanks: `chemical_tanks:[{tank:0b,stored:{id:"mekanism:oxygen",amount:8000}}]` — the field is `id`, not `chemical`.
- Machine per-side config lives in `component_config` as `config<ordinal>` int arrays in `RelativeSide` order (FRONT, LEFT, RIGHT, BACK, TOP, BOTTOM) plus `eject<ordinal>` booleans; transmission ordinals ENERGY=0, FLUID=1, CHEMICAL=2, ITEM=3, HEAT=4. `DataType` ordinals: NONE=0, INPUT=1, INPUT_1=2, INPUT_2=3, OUTPUT=4, OUTPUT_1=5, OUTPUT_2=6, INPUT_OUTPUT=7, ENERGY=8, EXTRA=9. Ejection needs BOTH the `eject<TransmissionType>` flag and a side whose `DataType` is one the machine's `addSlotInfo` actually declared for that transmission type — `getSidesForData` matches `DataType` by identity, so an undeclared value (e.g. plain `OUTPUT` on a machine that only exposes `OUTPUT_1`/`OUTPUT_2`, like the electrolytic separator, whose left tank is hydrogen and right tank is oxygen) silently ejects nothing. With `facing=north`, east→LEFT and west→RIGHT. `/setblock` does not apply item components, so these tags must always be written explicitly.
- Transmitter side connections use the `connection` int array (Direction order) documented in `docs/API_DELTAS.md`.
