# 移植风格审查 Prompt

```text
请审查最新提交是否偏离本项目最初的移植风格：

- 保留官方包名、类结构、机器继承与组合关系、领域算法和公共行为。
- 只修改必要的平台差异，优先使用 vanilla/Fabric 的真实能力，以最小 Mekanism 专用 adapter 接入。
- 复用真实 owner，不重复建立注册、配置、事件、缓存或生命周期框架。
- 保持注册 ID、NBT、配方、网络与存档语义，不凭接口名称相似就假定行为等价。
- 不通过删除行为、恒定返回、空实现、占位对象或调整源码清单来换取编译通过。
- 按完整行为边界修复，不遇到引用就扩展整个模块。

结合 Git 历史和官方源码核对。只读审查已提交内容，不修改代码、不扩大范围。有偏离就指出具体位置、依据和最小修正方向；没有发现就明确说明。
```

## 使用分级

- **完整审查（上面整段 prompt）**：涉及 owner 生命周期、网络/配置协议、NBT/codec、事务/能力语义、注册冻结的提交。
- **简审（提交信息里一两句结论即可）**：纯接线、重命名、文档、已有 owner 上的字段增补。
- 结论位置：对应里程碑活文档（`docs/milestones/M-*.md`）的"验收证据"，或提交信息；不单独提交。
